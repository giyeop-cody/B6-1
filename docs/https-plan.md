# HTTPS 보너스 후속 계획

## 현재 결정

사용 가능한 도메인이 없으므로 HTTPS를 성공했다고 표시하지 않는다. 먼저 HTTP 외부 접속과 Docker 배포를 완료한다.

## 도메인 준비 후 선택지

| 방법 | 장점 | 단점 |
|---|---|---|
| Nginx + Certbot | EC2 한 대에서 구조를 직접 배울 수 있음 | 인증서 자동 갱신과 80/443 관리 필요 |
| Application Load Balancer + ACM | AWS 관리 인증서를 사용 | ALB 비용과 구조가 과제 최소 범위를 크게 넘음 |
| CloudFront + ACM | CDN과 HTTPS를 함께 제공 | 캐시·도메인·인증서 리전 개념이 추가됨 |

초보 학습과 비용을 고려하면 도메인을 준비한 뒤 **Nginx + Certbot**을 먼저 검토한다. 다만 발급 시점의 Let’s Encrypt와 DNS 제공자 공식 문서를 다시 확인한다.

## 완료 조건

- [ ] 도메인 준비
- [ ] DNS A 레코드가 서버를 가리킴
- [ ] TCP 443 허용
- [ ] 유효한 인증서 발급
- [ ] `https://도메인/health`가 200
- [ ] HTTP가 HTTPS로 이동
- [ ] 인증서 자동 갱신 시험
- [ ] HTTPS 구성과 정리 방법 문서화
